Detailed Description

PulseAppChannelId Identifies an application-driven transport wire end-to-end.

Forwarded with every outbound PulseAppPacketCallback invocation and consumed by every pulse_app_transport_push call.

Bundle mode (today's WebRTC/Infinity calls): exactly one wire exists per call. The content and type fields are not meaningful — applications should read only kind (which is always PULSE_APP_CHANNEL_KIND_MUX). A zero-initialised PulseAppChannelId is the canonical bundle channel id.

SIP non-bundle mode: each m= section gets one (mux) or two (split RTP+RTCP) channels. content + type identify which m= section, and kind distinguishes the RTP wire from the RTCP wire when rtcp-mux is off.
