◆ pulse_options_set_app_transport()

PulseError pulse_options_set_app_transport ( Pulse *  client,
PulseAppPacketCallback  cb,
void *  user_data,
PulseDestroyCallback  destroy_cb 
)

Configure application-driven RTP transport.

Opts the client into application-driven transport for RTP/RTCP instead of the default UDP transport. Outbound packets are delivered to cb tagged with a PulseAppChannelId; inbound packets are fed back via pulse_app_transport_push using the same channel id. See PulseAppChannelId for bundle vs. non-bundle channel-id semantics.

Must be called before connection setup begins; later calls return PULSE_ERROR_ALREADY_CONNECTED. App-driven transport is mutually exclusive with the default port-/ICE-based transport — pick one before connecting.

Once a non-NULL cb has been installed the binding is sticky for the lifetime of the client: a subsequent call with cb == NULL returns PULSE_ERROR_INVALID_PARAMETER. To switch transport mode, destroy the client with pulse_free and create a fresh one. When the binding is replaced, the previous destroy_cb is invoked; final teardown happens inside pulse_free.

Parameters
clientThe Pulse handle.
cbOutbound packet callback. NULL is allowed only on a client that has never had a non-NULL binding installed; otherwise the call returns PULSE_ERROR_INVALID_PARAMETER. See PulseAppPacketCallback for threading and buffer-borrow semantics.
user_dataOpaque pointer passed to cb and destroy_cb. May be NULL.
destroy_cbOptional release callback for user_data. May be NULL.
Returns
PULSE_SUCCESS (0) on success, or a PulseError code in case of a failure.
