◆ PulseAppPacketCallback

typedef void(* PulseAppPacketCallback) (void *user_context, PulseAppChannelId channel_id, const uint8_t *data, int size)

PulseAppPacketCallback Callback invoked once per outbound packet that the client wants to deliver via application-driven transport.

Configured via pulse_options_set_app_transport().

Threading: the callback may be invoked on any internal media/streaming thread. The callback implementation MUST NOT call back into Pulse synchronously (e.g. it must not call pulse_disconnect, pulse_free, pulse_options_set_app_transport, ...). It IS safe to call pulse_app_transport_push() synchronously from this callback (e.g. for loopback testing or when the application's transport is itself synchronous).

Buffer borrow: the data buffer is borrowed and only valid for the duration of the call. The application MUST copy the bytes if it needs to retain them past return.

Backpressure: the callback returns void; outbound packets that cannot be sent are best-effort dropped by the application. This matches the underlying media layer semantics.

Channel id semantics: channel_id identifies the wire the packet flowed on. In bundle mode the application should ignore channel_id.content and channel_id.type and look only at channel_id.kind (always PULSE_APP_CHANNEL_KIND_MUX). In SIP non-bundle mode all three fields together identify the per-m= per-kind wire — see PulseAppChannelId.

Parameters
user_contextThe user context registered with the callback.
channel_idIdentifies the wire this packet flowed on.
dataBorrowed pointer to a packet (valid only for the duration of the call). In bundle mode this is a muxed RTP/RTCP packet; in split mode the channel_id.kind tells you whether this is an RTP or RTCP packet.
sizeLength of data in bytes.

enum PulseAppChannelKind

PulseAppChannelKind Identifies which wire a packet flowed on (or should flow on) when the application owns the transport.

Today bundle mode always uses PULSE_APP_CHANNEL_KIND_MUX (a single wire carrying both RTP and RTCP). SIP non-bundle (with a=rtcp-mux off) splits each m= section's transport into two wires: one PULSE_APP_CHANNEL_KIND_RTP and one PULSE_APP_CHANNEL_KIND_RTCP.

Enumerator

RTP+RTCP muxed on a single wire (the default).

PULSE_APP_CHANNEL_KIND_RTP 

RTP-only wire (rtcp-mux disabled on this m= section).

PULSE_APP_CHANNEL_KIND_RTCP 

RTCP-only wire (rtcp-mux disabled on this m= section).
